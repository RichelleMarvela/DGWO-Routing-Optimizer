# DGWO-Routing-Optimizer

Vehicle Routing Optimization for Relief Distribution under Flood Disaster Conditions

## Overview

This repository implements a reproducible pipeline for solving the Capacitated Vehicle Routing Problem with Time Windows (CVRPTW) under flood-disaster conditions. The proposed method (DGWO-F2OPT) couples a Grey Wolf Optimizer variant with a floating 2-opt local improvement and is compared against baseline metaheuristics (Classic GA, Adaptive GA, and MPSO).

The project uses CVRPLIB benchmark instances (e.g., A-n80-k10) and overlays stochastic flood conditions calibrated to BNPB historical distributions to generate realistic disaster scenarios.

## Key features

- Fuzzy Mamdani priority scoring (victims, damage, risk) to determine urgency per node.
- Stochastic flood-overlay calibrated to BNPB (damage levels, road accessibility, delay factors, dynamic blocking events).
- Time windows derived from priority scores to model time-critical humanitarian response.
- Hybrid optimizer DGWO-F2OPT (Grey Wolf Optimizer + Floating 2-opt local search).
- Baselines: Classic GA, Adaptive GA, Modified PSO (MPSO).
- Evaluation metrics: total distance, time-window penalty, risk exposure, response efficiency, and feasibility.

## Requirements

- Python 3.8+ recommended
- numpy
- pandas
- matplotlib

Install with pip:

pip install numpy pandas matplotlib

Or create a virtual environment:

python -m venv .venv
source .venv/bin/activate    # macOS / Linux
.venv\Scripts\activate     # Windows

If you add a requirements.txt, you can run:

pip install -r requirements.txt

## How to run

1. Clone the repository:

   git clone https://github.com/RichelleMarvela/DGWO-Routing-Optimizer.git
   cd DGWO-Routing-Optimizer

2. Start Jupyter and open the notebook:

   jupyter notebook VRP_Final_Complete_Fixed.ipynb
   # or
   jupyter lab

3. Run cells in order. Notebook sections include:
   - Installation & imports; reproducibility seed
   - Fuzzy Mamdani priority system
   - Data preparation and flood simulation overlay
   - Optimization algorithms and baselines
   - Evaluation, visualization, and result export

Notes:
- The notebook expects the CVRPLIB .vrp file (e.g., A-n80-k10.vrp). Put it in the repository root or update the path in the notebook.
- Experiments can be long; for quick testing reduce population sizes / iterations or use smaller instances.

## Reproducibility

The notebook sets GLOBAL_SEED = 42 to fix stochastic behavior for flood simulation and algorithm initialization. Keep execution order and seeds unchanged for consistent runs.

## Outputs & Results

Expected notebook outputs:
- fuzzy_mf_plot.png — membership functions plot
- Sample node table with attributes: victims, damage_level, road_access, priority_score, earliest/latest time, dynamic_t_block, will_block.
- Per-method experiment tables and plots for distance, TW penalty, risk, feasibility.

Consider exporting reproducible results to a `results/` folder when running long experiments.

## Limitations

- Flood simulation is stochastic and parameterized from historical data; field validation is recommended.
- Distances use Euclidean coordinates (not network routing). For real roads, integrate OSM routing.
- Fleet is modeled as homogeneous with simple capacity assumptions.

## Future work

- Integrate network-based routing (OpenStreetMap) and realistic travel times.
- Perform robust/stochastic optimization across multiple disaster realizations.
- Add real-time adaptation to route updates (dynamic blocking events) and heterogeneous fleets.
